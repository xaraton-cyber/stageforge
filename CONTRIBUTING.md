# Contributing

Thanks for helping improve live-performance audio workflows!

## Where help is needed

- Reproducible Windows setup and dependency pinning
- Cross-platform path handling and packaging
- More accurate BPM/downbeat detection and click verification
- GPU memory/error handling and progress feedback
- Automated tests using original or properly licensed synthetic audio
- Accessible GUI, translations and user documentation

## Workflow

1. Open an issue explaining the proposed change before large refactors.
2. Work in a focused branch; keep v4.4.1 behavior stable unless explicitly agreed.
3. Document reproduction steps, environment and before/after results.
4. Never commit model weights, API tokens, copyrighted songs, generated stems, or personal recordings without permission.
5. Submit a pull request referencing the issue.

**Licensing note:** The project owner must select a source-code license and contribution terms before accepting substantial outside code contributions. Until then, use issues/discussions for proposals and non-code feedback.
